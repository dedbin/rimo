# Исходящая почта на VPS Rimo

Контейнер содержит Postfix, Cyrus SASL и OpenDKIM. Rimo подключается по
приватной Docker-сети на порт 587 с обязательными STARTTLS и авторизацией.
Образ сохраняет man-страницы пакетов: штатный `postfix set-permissions` проверяет
их наряду с правами очереди. Проверка выполняется при сборке и при старте с
подключённой постоянной очередью.
Публичных SMTP-портов у контейнера нет. Для доставки используется прямое
соединение с MX получателя на TCP25 с обязательным STARTTLS и TLS 1.2 или новее.
Если MX не поддерживает шифрование, сообщение остаётся в очереди для повторной
попытки и код не передаётся открытым текстом.

## Настройки

Закрытый env-файл приложения должен содержать:

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=rimo@example.com
SMTP_PASSWORD=REPLACE_WITH_THE_GENERATED_SECRET
MAIL_FROM=no-reply@example.com
MAIL_HOSTNAME=example.com
MAIL_DOMAIN=example.com
MAIL_TLS_NAME=smtp.example.com
MAIL_DKIM_SELECTOR=rimo202610
RIMO_MAIL_TAG=REPLACE_WITH_RELEASE_TAG
RIMO_MAIL_PRIVATE_DIR=/srv/rimo/private/mail
```

`SMTP_PASSWORD` совпадает с содержимым файла `smtp-password` в приватном
каталоге. Пароль — случайная строка base64url длиной 32–128 символов; файл
принадлежит root и имеет режим 0600. Не передавайте пароль аргументом CLI.
Postfix разрешает этому пользователю отправку только от `MAIL_FROM`.
Значение `MAIL_FROM` должно быть `no-reply@MAIL_DOMAIN`.

Для приватного каталога создаются `smtp-password` и подкаталог `dkim`.
Закрытый ключ DKIM генерируется один раз и повторно используется после
пересоздания контейнера. Секреты и закрытые ключи не входят в Git.

## DNS и сертификат

Нужны A-запись для `SMTP_HOST`, корректные прямое/обратное разрешение
`MAIL_HOSTNAME`, SPF отправляющего IPv4, DKIM и DMARC для `MAIL_DOMAIN`.
Конкретные значения задаются в DNS своего домена; прежние записи сохраняются.

После первого запуска публичный DKIM TXT находится в приватном каталоге:
`dkim/<MAIL_DKIM_SELECTOR>.public.txt`. Это публичное значение для записи
`<MAIL_DKIM_SELECTOR>._domainkey.<MAIL_DOMAIN>`. Файл `.private` не публикуется.

Caddy получает отдельный публичный сертификат `MAIL_TLS_NAME`. SMTP читает
его из существующего `caddy-data` только для чтения. При запуске ожидается
валидный сертификат не более 120 секунд. Раз в минуту проверяется обновление:
совпадающая пара сертификат/ключ публикуется атомарно, затем Postfix перечитывает
настройки. Проверяется именно скопированная пара; изменение файлов Caddy во время
копирования не позволяет опубликовать несовпадающие ключ и сертификат. Маркер
применённой версии записывается после успешного reload, а при его ошибке
перезагрузка повторяется на следующей минуте. Старые наборы удаляются только
после успешного применения новой версии.

## Запуск и проверка

Из каталога релиза используются три Compose-файла в указанном порядке:

```sh
docker compose --project-name rimo --env-file /srv/rimo/private/rimo.env \
  -f docker-compose.yml -f deploy/ops/compose.yml -f deploy/mail/compose.yml \
  build mail
```

Для предварительного выпуска DKIM без запуска SMTP можно выполнить сервис с
entrypoint `/usr/local/lib/rimo-mail/configure-dkim.sh`. После публикации DNS
запускают Caddy отдельно, без запуска его зависимостей, и дожидаются сертификата:

```sh
docker compose --project-name rimo --env-file /srv/rimo/private/rimo.env \
  -f docker-compose.yml -f deploy/ops/compose.yml -f deploy/mail/compose.yml \
  up -d --no-deps caddy
```

Для первого запуска и восстановления с пустым `caddy-data` этот порядок
обязателен. Только после получения сертификата запускают SMTP и остальные
сервисы. Не добавляйте зависимость mail → Caddy: Caddy уже зависит от здорового
приложения, а приложение — от SMTP.

Перед включением подтверждения почты создают полную резервную копию. После
подготовки SMTP совместно обновляют приложение и collaboration с новой
миграцией, сохраняя прежний образ для отката. Подробнее — корневой README.

Для приёмки проверяют:

- Успешный STARTTLS и AUTH из контейнера приложения: `npm run mail:check`.
- Отказ без авторизации и с неверным паролем, отказ чужого отправителя.
- Получение настоящего кода во внешнем ящике и успешное подтверждение в Rimo.
- Заголовки SPF/DKIM/DMARC у получателя и отсутствие неожиданного deferred queue.

Очередь Postfix находится в отдельном named volume `mail-queue`. DKIM и SMTP
секреты сохраняются в приватном каталоге оператора и должны входить в его
зашифрованные резервные копии. Коды истекают через десять минут: старую очередь
при восстановлении сервиса не следует использовать как способ повторной
отправки кодов.

Проверка контейнера контролирует Postfix, OpenDKIM и срок TLS-сертификата.
Остановка любого из двух демонов завершает весь контейнер, после чего Docker
восстанавливает его. Логи ограничены 3 файлами по 10 МиБ, лимит памяти — 256 МиБ.
