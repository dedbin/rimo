# Переработка Rimo: рабочий план

## Цель

Получить рабочий и поддерживаемый сервис по `rimo-development-plan-2026-10-26.md`, сохранив существующий визуал. Пользователь разрешил установки, работу с агентами и промежуточные коммиты в отдельной ветке; выделил 20 часов продуктивной работы без привязки к календарю исходного плана.

## Решения

- Источник требований — `plan/rimo-development-plan-2026-10-26.md`; сроки из него не являются ограничениями.
- Визуал не перерабатывать. Существующие незакоммиченные изменения сохранить отдельно как исходное состояние.
- Предпочитать проверенные библиотеки; не усложнять код без функциональной необходимости.
- Для первого вертикального сценария принят snapshot persistence без журнала с честным ACK после COMMIT; подтверждение содержит и state vector, и delete-set.
- Секреты и локальные файлы окружения не включать в коммиты.
- Рабочего сервера нет; приёмка выполняется на отдельных локальных PostgreSQL и Docker-окружениях. Старые облачные ресурсы не нужны для запуска нового сервиса.

Исправлены SSR/hydration, постоянный каталог файлов и переносимость runtime URL в standalone.

Текущий общий прогон на `7b39e41` — 696 passed и 16 opt-in skipped,

Реальный отказ по квоте сохраняет черновик и позволяет восстановить архив.

На `221b` верхняя сетевая сцена 3000/500/50 и 5,18 МБ прошла: открытие до
3,23 с, доставка DOM p95 254,6 мс, десять reload без устойчивого роста heap.

100 экспортов без restart, PID 47→47, zombie/limit events 0. R08 сохранил

53,1/52,6 мс превышает 50. Mixed10 сохранил данные и браузерные бюджеты,
но Node p95 359,0 мс превышает 300.

Часовые попытки `317` и `221b` остановились на ACL timeout через 27 мин 28 с
и 45 мин 16 с. Добавлены числовая диагностика GC/heap/event loop, короткая
синтетическая накопленная история и yield очереди с проверками жизненного цикла
соединений. Исследованные альтернативы кодирования не перенесены в production.
Настройки GC не прошли полный час: последний вариант завершился receive-limit
через 38 мин 49 с. Deadline и защитные квоты не увеличены. Общая квота входящих
очередей готовится с учётом пути до авторизации; до независимого подтверждения
она не объявляется полной защитой. На своём восстановленном PostgreSQL прошли
703 теста, но это не заменяет часовую нагрузку.

Внешняя копия, настоящий VPS, публичный TLS, ответы по правовой модели и занятия
с людьми остаются условиями выпуска. Подробные факты, ограничения и версии:
[протокол проверок](verification-report-2026-10-27.md).
