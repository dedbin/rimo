# Переработка Rimo: рабочий план

## Цель

Получить рабочий и поддерживаемый сервис по `rimo-development-plan-2026-10-26.md`, сохранив существующий визуал. Пользователь разрешил установки, работу с агентами и промежуточные коммиты в отдельной ветке; выделил 20 часов продуктивной работы без привязки к календарю исходного плана.

## Решения

- Источник требований — `plan/rimo-development-plan-2026-10-26.md`; сроки из него не являются ограничениями.
- Визуал не перерабатывать. Существующие незакоммиченные изменения сохранить отдельно как исходное состояние.
- Предпочитать проверенные библиотеки; не усложнять код без функциональной необходимости.
- Для первого вертикального сценария принят snapshot persistence без журнала с честным ACK после COMMIT; подтверждение содержит и state vector, и delete-set.
- Секреты и локальные файлы окружения не включать в коммиты.
- Рабочего сервера нет; приёмка выполняется на отдельных локальных PostgreSQL и Docker-окружениях. Старые облачные ресурсы не нужны для запуска нового сервиса.

## Открытые вопросы

- Пользователь подтвердил: рабочего сервера нет, данные можно создавать с нуля; результат вести в отдельной ветке с понятными коммитами.
- Промежуточная ветка опубликована на GitHub: `dedbin/rimo`, `codex/service-rework`, подтверждённый remote HEAD `9cd0514`. Все 53 коммита на момент push имеют автора пользователя, совпадающего с профилем `dedbin`. Работа продолжается новыми коммитами; история авторства не переписывается.
- Добавлена правовая проверка РФ двумя агентами: персональные данные и договоры/оферта. Проекты сохраняются в `docs/legal/`, вопросы владельцу — в [отдельном файле](legal-questions-2026-10-27.md); публикация проектов как действующих документов пока не выполняется.
- Docker Desktop и отдельный PostgreSQL доступны и проверены. Для внешней зашифрованной копии пока не предоставлено хранилище; локальное восстановление проверяется независимо.
