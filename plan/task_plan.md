# Переработка Rimo: рабочий план

## Цель

Получить рабочий и поддерживаемый сервис по `rimo-development-plan-2026-10-26.md`, сохранив существующий визуал. Пользователь разрешил установки, работу с агентами и промежуточные коммиты в отдельной ветке; выделил 20 часов продуктивной работы без привязки к календарю исходного плана.

## Решения

- Источник требований — `plan/rimo-development-plan-2026-10-26.md`; сроки из него не являются ограничениями.
- Визуал не перерабатывать. Существующие незакоммиченные изменения сохранить отдельно как исходное состояние.
- Предпочитать проверенные библиотеки; не усложнять код без функциональной необходимости.
- Для первого вертикального сценария принят snapshot persistence без журнала с честным ACK после COMMIT; подтверждение содержит и state vector, и delete-set.
- Секреты и локальные файлы окружения не включать в коммиты.
- До28октября приёмка шла на отдельных локальных PostgreSQL и Docker-окружениях.
  Теперь целевой VPS развёрнут: [проверки сервера](server-rollout-2026-10-28/deployment-report.md).
  Старые облачные ресурсы не нужны для запуска нового сервиса.

## Открытые вопросы

- Пользователь подтвердил: рабочего сервера нет, данные можно создавать с нуля; результат вести в отдельной ветке с понятными коммитами.
- Промежуточная ветка опубликована на GitHub: `dedbin/rimo`, `codex/service-rework`, runtime source `662234d`. Настроенный автор `Some Great <black13dog@yandex.ru>` совпадает с профилем `dedbin`. Работа продолжается новыми коммитами; история авторства не переписывается.
- Добавлена правовая проверка РФ двумя агентами: персональные данные и договоры/оферта. Проекты сохраняются в `docs/legal/`, вопросы владельцу — в [отдельном файле](legal-questions-2026-10-27.md); публикация проектов как действующих документов пока не выполняется.
- Docker Desktop и отдельный PostgreSQL доступны и проверены. Для внешней зашифрованной копии пока не предоставлено хранилище; локальное восстановление проверяется независимо.

## Ошибки и ограничения

- `create_goal` сообщил, что цель уже существует. Подтверждено через `get_goal`: запрос пользователя активен, новая цель не нужна.
- В репозитории нет `scripts/codex_hook_emulation.py`; протокол применяется вручную.
- Из песочницы Git ref недоступен для записи; создание ветки и коммиты успешно выполнены с разрешённой эскалацией.
- Найден существующий bisect; не сбрасывается, исходные метаданные не меняются вручную.
- Исходные проверки: 29 тестов проходят; typecheck падает на двух старых `vi.Mock`; ESLint захватывал `.next` и выдавал тысячи ошибок сборки.
- При старте Docker Desktop был остановлен. Отдельный тестовый PostgreSQL создан без обращения к существующим БД; Docker engine затем запущен.
- Docker engine затем успешно запущен, полный Compose-стек проверен. Тестовый PostgreSQL изолирован и работает.
- Браузерный контроль обнаружил сбой активации пустого текста и blur по внешнему клику; оба исправлены и проверены повторно в настоящем Chromium.

Часовые попытки `317` и `221b` остановились на ACL timeout через 27 мин 28 с

отказал через 51 мин 32 с: queued32 при 8302 байтах, missing0/pending43.

подтвердил отказ32, drain/ACK64 и отказ65-го кадра. Это не лечение throughput.
