# Поддержка досок 20 МиБ: границы текущей реализации

Проверка исходников 27 октября 2026 года. Лимиты не изменялись, стенд и нагрузка
не запускались. Текущие **5 МиБ** — ограничение реализации; требование плана A
**20 МиБ** остаётся открытым. Увеличения одного параметра недостаточно.

| Контур | Действующая граница | Что требуется проверить или изменить |
| --- | --- | --- |
| Состояние | `DEFAULT_LIMITS.maxDocumentBytes` — 5 МиБ; полная проверка при загрузке и сохранении | Согласованно обновить [types](../collaboration-server/types.ts), [document](../collaboration-server/document.ts), [persistence](../collaboration-server/persistence.ts) |
| Входящий WebSocket | `maxPayload` и очередь соединения — 6 МиБ; сумма очередей 32 МиБ | Крупное сообщение не проходит независимо от свободной общей квоты |
| Скорость | Начальный burst 6 МиБ, пополнение 2 МиБ/с | 20 МиБ требуют больше 7 с даже с полным burst, без служебных байтов |
| Reconnect | `y-protocols.writeSyncStep2` кодирует missing delta одним сообщением | Нужен ограниченный способ передачи delta свыше 6 МиБ; текущий offline helper устраняет повтор, но не дробит ответ |
| Холодное чтение | Server→browser snapshot не ограничен входящим `maxPayload` сервера | Его успех не доказывает обратную передачу большой offline delta |
| ACK | Клиентский stateless JSON parser — до 8 млн символов | Проверить snapshot/delete-set большой истории; успешный COMMIT не должен остаться без распознаваемого подтверждения |
| PDF | Snapshot использует общий предел состояния; job — 3000 объектов, 20 страниц, 16 МиБ изображений, 28 МиБ JSON | Большой Yjs state не равен размеру видимого PDF-job; проверить оба ограничения отдельно |
| Архив | `board.yjs` ограничен теми же 5 МиБ; portable JSON — 32 МиБ; общий архив/распаковка — 256 МиБ | Проверить экспорт и импорт большого состояния, включая расширение в JSON |
| HTTP | Импорт архива разрешает 256 МиБ; остальные запросы — 11 MB | Для отдельного крупного HTTP transfer потребуется узкий маршрут с явным пределом |
| БД | `bytea` не задаёт 5 МиБ; общая квота состояний — 500 МиБ | Общая квота не заменяет защиту одной доски и RAM процесса |

Протокол установленного `y-protocols` находится в
`node_modules/y-protocols/sync.js`: `writeSyncStep2` вызывает
`Y.encodeStateAsUpdate(doc, stateVector)` и записывает один update. TCP и
WebSocket fragmentation не обходят предел собранного сообщения.
Входящие ограничения: [server](../collaboration-server/server.ts) и
[receive guard](../collaboration-server/receive-guard.ts). Клиентские:
[offline helper](../lib/collaboration/offline-sync.ts) и
[ACK parser](../lib/collaboration/protocol.ts).

Рабочая память включает canonical Y.Doc, shadow Y.Doc и полный encoded cache:
[validation cache](../collaboration-server/validation-cache.ts). Десять
заполненных 20-МиБ кэшей — уже около 200 МиБ только encoded buffers, без двух
декодированных деревьев, временных снимков и сокетов. Квота входящих байтов
не ограничивает эти расходы. Вместимость 20 МиБ этим анализом не доказана.

Поддерживаемый путь требует сначала решить транспорт: ограниченный допуск
крупной delta, небольшие сообщения с pacing, общий резерв, время жизни,
повторная ACL-проверка, длина/целостность и полная валидация до применения.
ACK остаётся после COMMIT. В установленном Hocuspocus готовое дробление
SyncStep2 не обнаружено; конкретная реализация здесь не выбрана и не написана.

После этого необходимы 20-МиБ cold/cache/offline reconnect, delete-heavy ACK,
архив → новая БД → PDF и измерение 1→5→10 горячих документов. Нынешний
[верхний сетевой fixture](../scripts/performance/network/upper-fixture.mjs)
и почти предельные WS-тесты рассчитаны на 5 МиБ. Их прежний успех нельзя
перенести на новый размер без повторной проверки.
