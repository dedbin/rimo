# Развёртывание Rimo на сервере

## Цель

Развернуть текущий Rimo на предоставленном пустом сервере с HTTPS для
`rimo-whiteboard.ru`, создать защищённую страницу прогресса с входящими
сообщениями владельца. Установки и настройка сервера разрешены пользователем.

## Этапы

- [x] Проверить SSH, ОС, CPU/RAM/диск, DNS и занятые порты.
- [x] Подготовить сервер, Docker и воспроизводимое окружение без секретов в Git.
- [x] Развернуть страницу прогресса и проверить отправку/чтение сообщения.
- [x] Развернуть текущую сборку Rimo, применить миграции, создать владельца.
- [x] Проверить публичные HTTPS/WSS, сохранение, гостя, PDF и архивы.
- [x] Проверить восстановление резервной копии в отдельный тестовый проект.
- [x] Настроить обновление, локальные копии и проверки; записать внешние остатки.
- [x] Провести независимое ревью, коммит и передачу адресов владельцу.

## Решения

- Ветка `codex/service-rework`; чужая папка выбора VPS не включается в коммиты.
- Подключение берёт секреты из игнорируемого `.env.server-access`.
- На скриншоте владельца A `@`/`www` направлены на сервер, проверяем живой DNS.
- Панель не получает токены Codex и не исполняет содержимое входящих сообщений.
- Остатки нагрузочной/правовой приёмки из прежнего протокола сохраняются.

## Ошибки

- В локальном Node нет отдельного пакета dotenv; используем штатный parser.
- Первый просмотр apt прерван Windows-кодировкой stdout на Unicode-символе;
  SSH-helper переведён на UTF-8, состояние удалённой установки проверяется отдельно.
- Авторитетные A-записи есть, но публичные резолверы пока получают NXDOMAIN
  из зоны `.ru`; выпуск публичного сертификата зависит от распространения делегации.
- `compose build app` не строит image: build-конфигурация у migrate.
  PDF image собран; приложение собирается через `compose build migrate`.
- Интерактивный `compose run` забрал остаток скрипта из stdin; локальный SSH-helper
  переведён на запуск отдельного приватного `.sh` файла с закрытым stdin.
- Первая core/restic копия завершилась успешно; последующая сводка сначала
  ошибочно читала NDJSON-прогресс как один JSON. Разбор исправлен без повторного backup.
- На Windows Kaspersky добавляет long-poll, поэтому networkidle не отражает
  готовность страницы. E2E ждёт DOM и явные UI/Saved критерии; антивирус не отключался.
- CLI через /srv/rimo/current молча не запускались из-за сравнения symlink argv.
  Общий realpath guard исправлен и покрыт96 targeted проверками с junction.
- Автодопуск отклонил новый root SSH key; вариант оставлен, используется исходный
  предоставленный доступ. Authorized keys сервера не изменялись.
- Создание фоновой пятиминутной automation отклонено до отдельного согласия.
  Вопрос владельцу задан асинхронно; повторов и обходных расписаний нет.
- Первый restore preflight не поддерживал отсутствие Health у Caddy в Docker29;
  исправлен безопасный inspect до создания тестовых ресурсов, повтор принят.
- После reboot первая HTTP-проверка ошибочно ожидала401 у общедоступного
  гостевого /v1/account. Проверены именно приватные темы: обе возвращают403.
  Первая ошибочная проба сохранена в локальном temp; ACL не изменялись.

## Состояние

Публичный Rimo прошёл5/5 E2E, панель — реальный вход и обмен через веб-форму.
Суточный backup с ops snapshots прошёл. Изолированный restore принят;
контрольная перезагрузка подтвердила автозапуск всех сервисов и трёх timers,
сохранность прежнего входа и истории панели. Failed units отсутствуют.
Получен реальный вопрос владельца в панели, ответ опубликован, cursor подтверждён.
Владелец выбрал проверку сообщений только во время работы в этом чате;
фоновое задание не создаётся.
