# Наблюдения и решения по переработке

## Исходное состояние

- Next.js 15.3.2, React 18, TypeScript, SVG-редактор.
- Текущие сервисы: Clerk, Convex, Liveblocks.
- Требования нового выпуска описаны в `rimo-development-plan-2026-10-26.md`.
- Локальные изменения внешнего вида существовали до начала этой работы; их нужно сохранить.
- Цель уже активна в Codex; длительность работы запрошена пользователем — 20 часов.

## Проверки

- Исходно: 29 тестов проходили; typecheck — две ошибки старого `vi.Mock`; ESLint захватывал `.next`; установленный `node_modules` не совпадал с lock.
- npm resolver дважды не смог согласовать старый Vite 6 с optional peers Better Auth. Создан чистый lock в `temp/dependency-lock`, выполнен `npm ci` без `--force`/`--legacy-peer-deps`.
- Установлены фиксированные Better Auth 1.7.13, Hocuspocus 4.7.1, Yjs 13.6.33, pg 8.23.1, Next.js 15.5.28, sharp 0.35.5. PostCSS 8.5.31 закреплён override из-за уязвимого транзитивного пакета Next 15.
- После обновления `npm audit` сообщает 0 известных уязвимостей. Typecheck общего проекта прошёл.
- Шрифты Geist/Poppins поставляются локально, сборка не обращается к Google Fonts.
- Тестовый PostgreSQL 18.1 запущен отдельно на localhost:55432, кластер и локальные секреты игнорируются Git.
- Docker Desktop запущен; доступны Linux engine 28.0.4 и Compose 2.34.0.
- Серверный агент: 8 тестов реального HTTP/auth/ACL/assets прошли; миграции идемпотентны.
- Агент совместной работы: 10 тестов WS/persistence/ACL/presence, включая SIGKILL после подтверждения записи на настоящем PostgreSQL, прошли.
- Первый полный прогон после замены инфраструктуры: 71 тест. Общий прогон 27 октября: 276 проверок прошли, 15 браузерных/Docker проверок включаются отдельно. Полный PDF-набор затем прошёл 40 проверок, включая 13 настоящих Chromium/PostgreSQL. `lint`, `typecheck` и production build проходят; окончательный счёт обновится после эксплуатационных проверок.
- Docker Compose собран и поднят: db/app/collaboration healthy, Caddy отвечает; `/api/health` через localhost:3080 возвращает 200. UID приложения — 1000, `.env`, `.env.local` и `.git` отсутствуют в runtime image. Базовые образы закреплены фактически проверенными digest.
- Браузер Chromium v1248: вход владельца, открытие dashboard/board без page errors; два независимых контекста прошли приглашение, совместные фигуры, перемещение и локальную отмену с сохранением чужой фигуры, viewer и отзыв активного editor.
- Браузер обнаружил дефекты двойного клика пустого текста и blur: немедленный pointer capture менял цель dblclick, а preventDefault мешал штатному blur. Захват отложен до реального drag, выход по внешнему клику явный. Повторная проверка native activation/drag/reload/Escape и полного text/image/reload сценария прошла без page errors.
- Старые 37 файлов `public/uploads` (около 8 МиБ) перемещены в игнорируемый `temp/legacy-public-uploads`, чтобы новая версия не выдавала прежние изображения публично. Нужные исходникам ссылки на этот каталог отсутствуют.
- Независимое ревью выявило и устранило mismatch presence, неверную обработку logical close на клиенте и отсутствие deadline повторной проверки прав при зависшей БД.

## Принятые контракты

- `Y.Doc`: `meta.schemaVersion=2`, `layers` как map per-field maps, `layerIds` как массив, rich text/LaTeX в `text:<layerId>` Y.XmlFragment. Версия 1 мигрирует только после строгой проверки, новый снимок подтверждается после COMMIT. Порядок нормализуется при чтении.
- Better Auth обслуживает аккаунты и анонимных гостей; публичный sign-up закрыт, владельцы создаются через CLI.
- Секрет приглашения в URL fragment, в БД только SHA-256; права и членство находятся вне CRDT.
- WebSocket проверяет cookie и Origin; повторная проверка сессии и ACL не реже пяти секунд.
- Первая реализация сохраняет полные snapshots без журнала. ACK содержит Yjs snapshot с delete-set и отправляется после COMMIT. Синхронизация транспорта не означает сохранение.
- Старые Convex/Clerk/Liveblocks исходники и публичные upload endpoints удалены, используются API с проверкой доступа и стабильные `/api/assets/:id`.
- Получение внешнего HTML для link cards временно заменено metadata по URL без сети; hardened preview — отдельная дальнейшая задача.

## Контроль после первого рабочего стека

- Коммиты `bdb4f09`, `bbe52fd`, `cd5ad1f` сохраняют квоты, native text gestures и исправления startup/hydration. `npm audit` после установки точных Playwright 1.64.1, Noto Sans 5.3.0 и остальных зависимостей — 0 известных уязвимостей.
- R06: согласованная копия PostgreSQL и файлов восстановлена в отдельном Compose-проекте; проверены SHA-256, прежний пароль и HTTP-доступ к изображению. Проверки ошибок tar, конкурентного запуска и SIGINT подтверждают возобновление остановленных сервисов. Внешнего репозитория пока нет, поэтому ежедневная внешняя копия не считается настроенной.
- Архив импортируется отдельным процессом в пустую тестовую БД: форматирование, LaTeX, orphan fragments, порядок и точные WebP-байты сохраняются с новыми ID и владельцем.
- R07: отдельные 10 тестов реального WS/PostgreSQL проверяют migration barrier и отказ восьми некорректных XML-обновлений до доставки соседу и изменения revision. Rich text ограничен согласованной схемой, KaTeX работает с trust=false.
- Production-сборка новой схемы прошла; сервер запущен через wrapper с абсолютным постоянным каталогом вложений. Полная браузерная приёмка R07 прошла в двух клиентах: безопасный Markdown, форматирование, inline/block LaTeX, совместный ввод, локальная отмена и reload без page errors.
- Исправлен фактический React 418 на Linux: SSR всегда начинает с русского, язык браузера восстанавливается после hydration; поведение подтверждено renderToString/hydrateRoot без suppressHydrationWarning. Повтор новой Docker-сборки ещё нужен.

## Дефекты, найденные повторными приёмками

- `f27d887`: rich text, формулы и сохраняемые области страниц. `29366cb`: `.rimo` и полная копия сервиса. Архив на пустой БД сохраняет также именованные фреймы и их порядок.
- `294bdd3`: устранён воспроизведённый PostgreSQL deadlock загрузки/импорта/первого сохранения. Блокировка строки доски берётся перед бюджетом документов; проверка с `pg_blocking_pids` подтверждает завершение трёх транзакций.
- `8def7d7`: валидация служебных данных Tiptap согласована с реальными node boundary transfers. Новый E2E сценарий bold→Enter раньше отключал клиента; публичный Editor regression и браузерный повтор проходят.
- `051c34f`: перенос изображений между досками создаёт файлы в собственной границе доступа, учитывает квоты и сохраняет rich AST в одной операции undo. Проверены source404/destination200 у гостя, фактическое декодирование, dedup, отказ без частичной вставки, ZIP и reload.
- Исправлено зависание картинок: скрытый `NextImage` с lazy loading не начинал загрузку. Для уже отобранных viewport culling изображений включён eager loading. После пересборки другой BUILD_ID, тот же WebP SHA-256 и видимое изображение подтверждены браузером.
- PDF: отдельный Linux worker с включённым Chromium sandbox и лимитом 768 МиБ создал 20 контрольных страниц за 660 мс (1201 мс с inspect); русский текст, три локальные гарнитуры, code, порядок и размеры листов проверены pypdf/pdfplumber, PNG просмотрен. Это Ryzen 5 7600X/12 logical CPUs, не замер VPS и не параллельного урока.
- PDF review закрыл неверные пропорции изображения, расхождение контраста стикеров и разные шрифты холста/печати. Замер тяжёлого preview показал блокировку event loop приложения до 407 мс; генерация HTML перенесена в прежний отдельный worker и его общую ограниченную очередь. App больше не читает шрифты через fs; временный tracing удалён. Реальная регрессия отмены body после response.end закрывает slot без ожидания 30-секундного таймаута. Коммит `6cbf531`.
- Чистая standalone-сборка прошла четыре UI E2E и проверку CSS/woff2 через HTTP. Три адреса WebSocket, включая старое имя env, работают с одним BUILD_ID без пересборки. Postbuild удаляет dotenv из standalone: Next включал корневой .env, из-за чего его новый ключ маскировал legacy-only сценарий. Секреты и адреса поступают только при запуске.
- R08: контрольная сцена содержит 3000 объектов/500 видимых/50 декодированных изображений. Диагностика подтвердила конечное перемещение 500 объектов и один undo, но авто-высота текстов создавала десятки одновременных updates. Коммит `1f08376` объединяет измерения в одну транзакцию за кадр; численные бюджеты ещё нужно повторить на итоговой сборке.
- Короткий профиль 50 соединений/10 редакторов на пяти досках по 3000 объектов пока не прошёл: задержка выросла до секунд, затем сработал receive limit. CPU совместного процесса оказался ограничением. Проверенная копия Yjs переиспользуется с полным сравнением бинарного состояния, включая pending structs/delete sets; строгая валидация сохраняется. Нужен повтор после сборки.
- Аудит подтвердил две ошибки комнат: uppercase UUID создавал второй Doc на ту же строку PostgreSQL и мог перезаписать подтверждённые правки; одновременная auth обходила maxOpenDocuments. `b352b4f` исправляет обе границы, lifecycle проверенной shadow и TTL доступа; реальные WS/PG-регрессии прошли. Проверки полного состояния сохранены: delta не обнаруживает in-place изменение прежнего JSON prefix и не заменяет полную сверку.
- Постоянный E2E набор прошёл 4/4 сценария: collaboration, rich text, clipboard и PDF/archive. В управляемом запуске Windows sandbox не позволил Playwright завершить собственные дочерние серверы; после проверки ancestry остановлены только эти деревья, runner завершился успешно. CI browser/PDF шаги подготовлены, удалённый workflow не запускался: ветка не отправлялась.
