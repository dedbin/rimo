## Существенные особенности

- **Шрифты Fontsource.** Geist, Geist Mono, Noto Sans, Noto Sans Mono, Noto Serif
  и Poppins фактически подключены локально в `app/layout.tsx`, `app/globals.css`
  и компонентах интерфейса. Каждый пакет содержит собственный copyright и OFL-1.1.
  При передаче шрифтов нужно сохранять эти уведомления и полный текст OFL;
  продажа шрифта отдельно запрещена, изменения требуют проверки Reserved Font
  Names. Условие о сохранении OFL не переводит созданный документ под OFL.
  Основание: локальные LICENSE и [официальный текст OFL](https://openfontlicense.org/open-font-license-official-text/).
- **KaTeX.** Поле лицензии пакета — MIT, но у всех 20 TTF в `dist/fonts` в таблице `name`
  (ID 0/13/14) указаны Design Science, Khan Academy, OFL-1.1 и 12 Reserved Font
  Names. [`generate_fonts.py`](../../node_modules/katex/src/fonts/generate_fonts.py)
  сохраняет из той же модели TTF, WOFF и WOFF2. Отдельного полного текста OFL в
  установленном `katex` нет: одного его MIT-файла для шрифтов недостаточно.
  В [FONT-NOTICES.txt](../../public/licenses/FONT-NOTICES.txt) подготовлены copyright,
  Reserved Font Names и общий полный текст OFL для KaTeX и шести Fontsource.
- **sharp / libvips.** Apache-2.0 у JS-пакета `sharp` не описывает все нативные
  библиотеки. Локальный Windows-пакет `@img/sharp-win32-x64@0.35.5` декларирует
  `Apache-2.0 AND LGPL-3.0-or-later`; его `versions.json` указывает libvips 8.18.7.
  Для Linux glibc x64/arm64 lockfile предусматривает `@img/sharp-libvips-*@1.3.4`
  с `LGPL-3.0-or-later`. Эти Linux-пакеты здесь не установлены и не извлекались
  из образа. [Локальный README Windows-пакета](../../node_modules/@img/sharp-win32-x64/README.md)
  отдельно перечисляет LGPL, MPL, BSD, MIT и другие лицензии; его LICENSE
  содержит только Apache-2.0, отдельных текстов LGPL/GPL в этом пакете не найдено.
  [Первичный список sharp-libvips](https://github.com/lovell/sharp-libvips/blob/main/THIRD-PARTY-NOTICES.md)
  также опубликован upstream; текущая ветка не заменяет проверку конкретного выпуска.
- **MIT и Apache не отменяют уведомления.** Next, React, Yjs, Hocuspocus,
  Better Auth и перечисленные Tiptap-пакеты содержат MIT; из этого нельзя делать
  вывод о лицензии каждого встроенного или транзитивного компонента. У `marked`
  файл дополнительно содержит условия Markdown с copyright John Gruber,
  сохранением уведомлений и запретом использовать имена для продвижения.
  У Lucide сохранено упоминание частей Feather (MIT). У `playwright` и
  `playwright-core` есть NOTICE о коде Puppeteer; его нужно сохранять вместе
  с Apache-2.0. У изменённых Apache-файлов нужны отметки об изменениях:
  [раздел 4 лицензии](https://www.apache.org/licenses/LICENSE-2.0).

## Что сохраняет текущая упаковка

Это вывод из рецептов сборки, без запуска Docker и проверки готового образа.

| Поставка | Что следует из исходников | Что ещё требуется |
| --- | --- | --- |
| Исходный репозиторий | Корневой [LICENSE](../../LICENSE) содержит MIT и `Copyright (c) 2025 dedbin` | Сохранить его и собственные уведомления компонентов при копировании или включении зависимостей |
| Основной [Dockerfile](../../Dockerfile) | В runtime сначала копируется весь `node_modules` после `npm ci --omit=dev`, включая package LICENSE/NOTICE; затем standalone и collaboration. Явно копируются корневой LICENSE и `licenses/FONT-NOTICES.txt` | Проверить тексты в собранном образе и остальные встроенные компоненты |
| [export-worker/Dockerfile](../../export-worker/Dockerfile) | `npm ci --omit=dev` оставляет полный production `node_modules` и его лицензии; явно копируются корневой LICENSE и `licenses/FONT-NOTICES.txt` | Проверить тексты в собранном образе и наследуемые лицензии браузеров и базового образа |
| Браузерные JS/CSS/WOFF2 | Единственный исходник уведомлений — `public/licenses/FONT-NOTICES.txt`, доступный как `/licenses/FONT-NOTICES.txt`; [`prepare-standalone.mjs`](../../scripts/prepare-standalone.mjs) переносит `public` и `.next/static` | Проверить HTTP-выдачу после сборки и уведомления фактически включённого клиентского кода сверх шрифтов |

## Практические действия перед соответствующей поставкой

1. **Статические файлы:** проверить выдачу подготовленного файла
   `/licenses/FONT-NOTICES.txt` в окончательной поставке.
   Сверить итоговые клиентские пакеты и вложенные LICENSE/NOTICE;
   подготовленный файл охватывает шрифты, а не все браузерные зависимости.
2. **Контейнеры и архивы:** проверить включение корневого LICENSE и уведомлений,
   сохранить исходные package LICENSE/NOTICE, включая Playwright и вложенные
   лицензии Next. Наличие ссылок в этой таблице не заменяет тексты в поставке.
3. **Linux native bundle:** до передачи образа зафиксировать архитектуру,
   `versions.json`, полный набор лицензий и соответствующие исходники
   LGPL-компонентов. Определить применимый способ предоставления исходников и
   замены/повторной сборки этих частей; одних файлов LICENSE недостаточно для
   такого вывода. Условия Combined Works описаны в разделе 4 LGPLv3, условия
   передачи исходников — в GPLv3 §6 ([текст в реестре SPDX](https://github.com/spdx/license-list-data/blob/main/text/LGPL-3.0-or-later.txt)).
   Страницы GNU при этой сверке были недоступны; применимость к конкретной
   поставке остаётся отдельной проверкой.
4. **Повторять при выпуске:** обновлять инвентарь после изменения lockfile;
   проверить базовые Node/Debian/Ubuntu-слои, браузерные бинарники и остальные
   транзитивные компоненты в фактической поставке. Текущий обзор их не закрывает.

Инвентарь, публичный исходник уведомлений и COPY в обоих Dockerfile подготовлены.
Проверка фактической HTTP-выдачи и содержимого новых образов ещё не выполнена;
полная проверка лицензий поставки остаётся отдельным условием распространения.
