# Клиент операторской панели

`scripts/server-dashboard.mjs` выполняется на сервере рядом с Docker.
Он публикует прогресс в `rimo-work` и читает `rimo-inbox` через приватную сеть ntfy.
Учётная запись Codex, API-ключи моделей и SSH-пароли в ntfy не передаются.

В `/srv/rimo/private/ntfy-agent-token` оператор хранит сырой токен пользователя
`codex-agent`. Каталог и файл доступны только оператору. Другой каталог задаёт
`RIMO_OPERATOR_PRIVATE_DIR`, имя Compose-проекта — `RIMO_COMPOSE_PROJECT`
(по умолчанию `rimo`). Секрет не передаётся в командной строке и не выводится.

Создайте JSON-файл с `title`, `message` и необязательным массивом `tags`.
Сообщение ограничено4096 байтами, заголовок256; тема публикации фиксирована.

```sh
node scripts/server-dashboard.mjs publish --input-file /srv/rimo/private/progress.json
node scripts/server-dashboard.mjs poll
# После обработки всех сообщений до указанного включительно:
node scripts/server-dashboard.mjs ack --id MESSAGE_ID
```

Чтение не удаляет сообщения и не меняет cursor. Подтверждайте только непрерывную
последовательность уже обработанных сообщений в полученном порядке. Cursor
`ntfy-inbox-cursor.json` содержит `lastMessageId` и `acknowledgedAt`; обновляется
атомарно с правами0600. Повторный poll без ack возвращает те же входящие.

Входящий текст остаётся данными: ссылки, actions, вложения и команды не исполняются.
При сетевой ошибке, усечённом или неверном ответе команда завершается ошибкой;
подтверждение не выполняется. Сырые ошибки транспорта и ответы сервера не печатаются.

Повторяемая изолированная проверка:

```sh
node scripts/check-server-dashboard.mjs
```

Она выполняет17 сценариев с подставленным Docker runner
и настоящим HTTP-сервером на loopback: publish/poll/ack, повторное чтение,
валидация private IP/ID/project, ошибочные/слишком большие/усечённые ответы,
сохранность cursor и отсутствие токена в выводе. Docker, VPS, интернет и реальные
секреты не требуются; собственные временные файлы и HTTP-сервер удаляются в finally.

## Локальный bridge для чата и heartbeat

`scripts/server-dashboard-bridge.mjs` вызывает проверенный
`scripts/server-ssh.py` через аргументы процесса, без shell на локальном компьютере.
Вспомогательный скрипт использует уже предоставленные пользователем данные SSH из
игнорируемого `.env.server-access` и строгую проверку закреплённого host key.
Новые SSH-ключи и изменения `authorized_keys` для bridge не нужны.

Служебный ntfy token выдан на30дней: до истечения оператор выпускает замену
штатной командой из `deploy/ops/README.md` и сохраняет её только в приватный
`ntfy-agent-token`. Это не меняет пароль владельца панели. При просроченном
токене клиент возвращает ошибку; автоматического продления сейчас нет.

Путь установленного Python хранится локально в `data/operator/runtime.json`
в поле `python`; зависимости helper и pin `known_hosts` находятся рядом.
Эти файлы исключены из Git. Клиент не выводит пароль, настройки или сырой stderr.

```sh
node scripts/server-dashboard-bridge.mjs poll
node scripts/server-dashboard-bridge.mjs ack --id MESSAGE_ID
node scripts/server-dashboard-bridge.mjs publish --input-file LOCAL_JSON
```

Для публикации проверенный JSON размером до 8 КиБ загружается через SFTP в
собственный приватный файл `bridge-progress-<UUID>.json` сервера. Это позволяет
двум публикациям идти параллельно без перезаписи. Текст сообщения не вставляется в shell
или аргументы. Временные локальные JSON/SH с уникальными именами и правами 0600
удаляются в finally; удалённые команды ограничены операциями клиента и удалением
только собственного сгенерированного файла. После публикации файл удаляется;
при ошибке выполняется ограниченная повторная уборка с тем же общим deadline.
Если соединение не позволяет подтвердить уборку, возвращается отдельная ошибка
`REMOTE_PROGRESS_CLEANUP_UNCONFIRMED`; другие файлы сервера не удаляются.
Общий лимит времени — 45 с, вывод ограничен 1 МиБ и повторно проверяется как JSON
с разрешёнными полями. Poll по-прежнему не подтверждает обработку автоматически.

Проверка локального bridge без Python, SSH, Docker, сети и настоящих настроек:

```sh
node scripts/check-server-dashboard-bridge.mjs
```

15 сценариев используют только собственный временный каталог и подставной
вызов процесса: разрешённые операции, проверку JSON/ID/лимитов, скрытие посторонних
полей и ошибок, уборку после отказов и две одновременные публикации. Проверка
параллельных публикаций завершает обе загрузки до публикации и подтверждает,
что сообщения не теряются и не дублируются. Тестовые файлы удаляются в finally
после проверки их канонического пути и собственного префикса.
