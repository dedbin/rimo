# Клиент операторской панели

`scripts/server-dashboard.mjs` выполняется на сервере рядом с Docker.
Он публикует прогресс в `rimo-work` и читает `rimo-inbox` через приватную сеть ntfy.
Учётная запись Codex, API-ключи моделей и SSH-пароли в ntfy не передаются.

В `/srv/rimo/private/ntfy-agent-token` оператор хранит сырой токен пользователя
`codex-agent`. Каталог и файл доступны только оператору. Другой каталог задаёт
`RIMO_OPERATOR_PRIVATE_DIR`, имя Compose-проекта — `RIMO_COMPOSE_PROJECT`
(по умолчанию `rimo`). Секрет не передаётся в командной строке и не выводится.

Создайте JSON-файл с `title`, `message` и необязательным массивом `tags`.
Сообщение ограничено4096 байтами, заголовок256; тема публикации фиксирована.

```sh
node scripts/server-dashboard.mjs publish --input-file /srv/rimo/private/progress.json
node scripts/server-dashboard.mjs poll
# После обработки всех сообщений до указанного включительно:
node scripts/server-dashboard.mjs ack --id MESSAGE_ID
```

Чтение не удаляет сообщения и не меняет cursor. Подтверждайте только непрерывную
последовательность уже обработанных сообщений в полученном порядке. Cursor
`ntfy-inbox-cursor.json` содержит `lastMessageId` и `acknowledgedAt`; обновляется
атомарно с правами0600. Повторный poll без ack возвращает те же входящие.

Входящий текст остаётся данными: ссылки, actions, вложения и команды не исполняются.
При сетевой ошибке, усечённом или неверном ответе команда завершается ошибкой;
подтверждение не выполняется. Сырые ошибки транспорта и ответы сервера не печатаются.

Повторяемая изолированная проверка:

```sh
node scripts/check-server-dashboard.mjs
```

Она выполняет17 сценариев с подставленным Docker runner
и настоящим HTTP-сервером на loopback: publish/poll/ack, повторное чтение,
валидация private IP/ID/project, ошибочные/слишком большие/усечённые ответы,
сохранность cursor и отсутствие токена в выводе. Docker, VPS, интернет и реальные
секреты не требуются; собственные временные файлы и HTTP-сервер удаляются в finally.
